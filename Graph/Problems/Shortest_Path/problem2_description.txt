Mountain Transit Link

A regional transport planner is studying a set of remote settlements connected by roads that climb, bend, and occasionally fork around difficult terrain. The settlements are numbered, but the numbering is only for reference; what matters is that one settlement has been chosen as the origin for a supply run and another settlement has been chosen as the final stop. The roads between them each carry a cost that reflects distance, elevation change, and maintenance difficulty. Some roads are quick but steep, while others are longer but easier on the vehicle. The planner needs a route that reaches the destination from the origin with the smallest total cost among all possible valid routes in the network.

At first glance, several paths may appear plausible. One route may use a direct but expensive ridge road. Another may pass through two or three quieter valleys and end up cheaper overall. A third may wander through a service junction that looks promising until the total cost is added up. The task is to reason about the full weighted structure, not just the first edge leaving the start. If the graph offers a cheaper combination of intermediate stops, that combination should be preferred even if it seems longer in terms of hops.

The planner does not need to inspect every settlement, and there is no need to create a loop that returns to the origin. The assignment ends when the destination is reached. Likewise, the route is not about covering all nodes, counting all roads, or finding a route that touches as many places as possible. It is a focused question about the cheapest way to move from one designated point to another while following the available weighted connections exactly as defined.

The network may contain several branching choices, and some branches may look attractive before a full comparison is made. That is intentional. The correct answer should identify the minimum-cost walk from the chosen start to the chosen end using the graph’s edge weights as the only criterion. The output should therefore reflect the best possible travel plan between those two endpoints, not a partial heuristic guess.

In practical terms, the planner often uses this kind of answer to compare fuel usage, delivery time, and vehicle wear. A route that is geographically longer can still be the least expensive if it avoids heavy links or difficult transitions. That is why the graph must be read as a complete cost network rather than as a simple map of nearby settlements. The objective is not to maximize the number of stops or to explore the whole region. It is only to identify the cheapest valid connection from the origin to the destination, no matter how many intermediate settlements appear along the way.

The planner also needs the result to be stable enough for repeated use. The same road network may be considered again under a slightly different shipment schedule, and the answer should still be the cost-minimizing route for the current endpoints. This makes the problem a pure weighted path selection task: given the fixed start and end, and given every allowed road between them, choose the sequence that keeps the overall cost as low as possible.
